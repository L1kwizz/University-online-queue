# University Hub — Электронная очередь деканата

Веб-приложение для записи студентов в деканат через цифровой талон. Студент получает номер в очереди онлайн, сотрудник деканата вызывает студентов к окнам, а на публичном табло видно, кого вызывают.

Проект построен на Next.js 16 (App Router), React 19, Tailwind CSS v4 и Payload CMS 4 (beta).

## Возможности

- Вход по почте и паролю для студентов и сотрудников деканатов.
- Два независимых деканата: **технический** и **гуманитарный**. Каждый со своими окнами, номерами талонов и очередью.
- Студент выбирает только цель обращения. Направление определяется его аккаунтом.
- Студент видит свой талон, позицию в очереди и ожидаемое время, может отменить запись.
- Сотрудник видит очередь только своего деканата, вызывает следующего, назначает конкретного студента в свободное окно, завершает приём или отмечает «не явился».
- Публичное табло (без ФИО студентов) с текущими вызовами и очередью ожидания.
- Звуковое оповещение при вызове.
- Имитация задержки базы данных при входе (1,2–2 с), чтобы интерфейс вёл себя как с реальной БД.

## Структура

```
src/
  app/
    (frontend)/            Страницы сайта и API очереди
      queue-api/           REST-маршруты (вход, талоны, окна, табло)
    (payload)/             Админка Payload (не редактировать)
  collections/             Коллекции Payload: users, departments, counters, queue-tickets, media и др.
  features/queue/          Интерфейс очереди (React)
    constants.ts           Цели обращения, отделы, окна, демо-аккаунты
    QueueApp.tsx           Корневой компонент, опрос API раз в 4 с
    LoginScreen.tsx        Экран входа
    StudentDashboard.tsx   Кабинет студента
    StaffDashboard.tsx     Панель сотрудника
    PublicBoard.tsx        Табло
  lib/
    payload.ts             Получение клиента Payload и поиск по slug

```

## Роли и доступ

| Роль | Деканат | Что видит и может |
|---|---|---|
| Студент | Технический / гуманитарный | Свой талон, позицию в очереди. Может создать талон и отменить его. ФИО других студентов не видит. |
| Сотрудник | Технический / гуманитарный | Очередь своего деканата, окна, вызовы, завершение и пропуск талонов. |

Доступ к талонам и окнам ограничен на уровне коллекций Payload (`access`) и проверяется в API. Студент не может указать чужой деканат или владельца талона: эти поля заполняются на сервере.

## Демо-аккаунты

Пароли задаются в `src/features/queue/constants.ts` и используются только для демонстрации.

| Почта | Пароль | Роль | Деканат |
|---|---|---|---|
| student.tech@university.kz | Tech-Student-2026 | Студент | Технический |
| student.hum@university.kz | Hum-Student-2026 | Студент | Гуманитарный |
| staff.tech@university.kz | Tech-Staff-2026 | Сотрудник | Технический |
| staff.hum@university.kz | Hum-Staff-2026 | Сотрудник | Гуманитарный |

## Запуск локально

Требования: Node.js 24 и pnpm 10.

```bash
pnpm install
pnpm exec next dev --port 3001 --hostname 0.0.0.0
```

Откройте `http://localhost:3001`.

База данных локально — SQLite-файл `local.db` в корне проекта. Демо-данные (отделы, окна, пользователи) создаются автоматически при первом входе. Чтобы начать заново, остановите сервер и удалите `local.db`.

Без переменной `FIGMA_EID` конфигурация Payload использует SQLite. Если переменная задана (Figma Make), используется платформенный `buildFigmaConfig`.

## Основные маршруты API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/queue-api/auth/login` | Вход |
| POST | `/queue-api/auth/logout` | Выход |
| GET | `/queue-api/auth/me` | Текущий пользователь |
| GET | `/queue-api/tickets` | Талоны деканата и окна |
| POST | `/queue-api/tickets` | Создать талон (студент) |
| PATCH | `/queue-api/tickets/:id` | Вызвать, завершить, пропустить, отменить |
| POST | `/queue-api/counters/:id/call-next` | Вызвать следующего к окну (сотрудник) |
| GET | `/queue-api/board?direction=tech\|hum` | Данные табло без ФИО |

## Известные ограничения

- Опрос обновлений раз в 4 секунды. Для реального времени можно перейти на SSE.
- Демо-пароли хранятся в коде. Перед продакшеном их нужно убрать.
- Переход талона между деканатами не реализован.
- Регистрация и восстановление пароля — только имитация в интерфейсе.
